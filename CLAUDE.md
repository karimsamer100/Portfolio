# Karim Portfolio — Claude Code Project Rules

## Context files
- `01_PERSONAL_PROFILE.md`: factual reference about Karim. It is **not** permission to publish every fact.
- `02_PORTFOLIO_CREATIVE_BRIEF.md`: creative ambition, visitor goals and acceptance standards.
- `03_CLAUDE_CODE_SETUP.md`: optional environment and tools guidance; read only when configuring tooling.
- At the start of the **first discovery/creative session**, read the first two files fully. Do not reread entire files on every turn unless the relevant facts changed.

## Working contract
1. We are building an exceptional, original personal brand website, not a generic developer template.
2. Do not assume a chosen art direction, layout, palette, framework, navigation or project shortlist. Propose and justify concepts first; seek Karim's approval before a full build.
3. Use only verified personal claims and authentic project material. Never invent metrics, work history, testimonials, images or credentials. Distinguish team contributions and unverified numbers.
4. Keep private discussion, implementation process notes and unpublished personal details **out of public website copy**.
5. Work in **small, reviewable phases**. For each phase: state goal, implement, run relevant checks, inspect actual browser output, and summarize exactly what changed and what remains.
6. Prioritize a signature creative concept, sophisticated craft, professional clarity, accessibility, mobile quality and performance equally. Avoid pointless effects and generic AI aesthetics.
7. Use existing CLI/build/test tools before adding dependencies or services. Do not install many overlapping MCP servers/plugins. Ask before major dependencies, external services or paid APIs.
8. Keep responses concise: decisions, evidence, next milestone. Avoid repeating the entire brief or printing long logs unless specifically needed for a blocker.

## Verification
- When an app exists, discover its actual commands and run relevant build, typecheck, lint and tests after changes.
- Check desktop, mobile, keyboard navigation and reduced motion for user-facing work.
- Screenshots and browser inspection are mandatory for visually significant changes; passing unit tests is not visual QA.
- Never claim a site or third-party integration is deployed, connected or verified when it has not been tested.

## First assignment
Review `01_PERSONAL_PROFILE.md` and `02_PORTFOLIO_CREATIVE_BRIEF.md`; conduct a *focused creative discovery*, then propose distinct original creative directions with reasoning, visitor journeys and visual evidence. **Do not generate a full default portfolio on the first pass.**
