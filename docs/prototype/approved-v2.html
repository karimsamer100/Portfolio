      Selected work · 01  /  أعمال

      1,000 requests. Three machines. None lost.

      A distributed RAG system built as a three-person group project for CSE354, 2026. A master scheduler routes LLM questions across worker machines, and each worker runs its own retrieval pipeline and local model.

      0requests completed · 0 failed
      Avg latency at 1,000 requests
      Round Robin16.69 s
      Load-Aware12.48 s
      ~25% lower latency · ~27% higher throughput

      The detail

      Built with
      Python, FastAPI, ChromaDB, all-MiniLM embeddings, Ollama running qwen2.5:1.5b on each worker, ngrok between machines.
      What it does
      Thread-safe task queue, three routing strategies, heartbeat health checks, and failed tasks re-queued up to three times.
      Evidence
      Benchmarks at 50, 100, 500 and 1,000 concurrent requests, reported in the project README and report.

      To confirm with Karim before launch.

      Selected work · 02  /  أعمال

      Answers grounded in 123,000 real support cases.

      A customer-support assistant that finds similar past cases before an LLM writes the reply. FAISS search over MiniLM embeddings, served by FastAPI with API-key auth, metrics and feedback logging, and deployed with Docker on Railway.

      Example question
      top_k = 5 nearest cases retrieved · then passed to the LLM as context

      The detail

      Built with
      Python, sentence-transformers all-MiniLM-L6-v2, FAISS, FastAPI, Docker, Railway, optional MLflow tracking.
      Data
      About 123,000 AmazonHelp support pairs, cleaned and categorised. The public demo uses a 20,000-row index.
      Evidence
      Health, metrics and dashboard endpoints, an evaluation script, and docs for deployment, security and retraining.
